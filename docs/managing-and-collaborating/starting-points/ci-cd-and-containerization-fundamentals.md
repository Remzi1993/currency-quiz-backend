# CI/CD & Containerization Fundamentals

I use GitHub Actions and Docker for this backend. CI means Continuous Integration; [CD means delivery or deployment](https://about.gitlab.com/topics/ci-cd/): keeping changes release-ready or releasing them automatically.

| Topic                     | Explanation and project evidence                                                                                                                                                                                                                   | Files or reference                                                                                                                                                        |
|---------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Pipeline stages           | Lint checks quality → tests verify behaviour → build packages → deploy releases. My workflow runs OpenAPI validation → tests → JAR build. Docker builds and deployment are separate.                                                               | [ci.yml](../../../.github/workflows/ci.yml)                                                                                                                               |
| Reading logs              | Find the failed Actions step, then its exit/assertion failure and first relevant error. Negative tests can log expected errors while passing. A hosted failure/fix example remains unrecorded.                                                     | [ServerTest.kt](../../../src/test/kotlin/ServerTest.kt), [CI/CD Basics](ci-cd-basics.md)                                                                                  |
| Container versus VM       | Containers share their runtime host's kernel; VMs have their own guest OS and kernel. Docker Desktop's Linux containers use a Linux kernel, for example through WSL 2 on Windows.                                                                  | [Docker explanation](https://docs.docker.com/get-started/docker-concepts/the-basics/what-is-a-container/), [WSL 2 backend](https://docs.docker.com/desktop/features/wsl/) |
| Dockerfile instructions   | `FROM` selects a base/stage; `WORKDIR` sets the directory; `COPY` adds files; `RUN` executes build-time commands. `EXPOSE` documents a port without publishing it.                                                                                 | [Dockerfile](../../../Dockerfile)                                                                                                                                         |
| Startup and health checks | `CMD` supplies default startup commands/arguments. Here, `ENTRYPOINT` starts Java; `HEALTHCHECK CMD` runs the HTTP probe.                                                                                                                          | [Dockerfile](../../../Dockerfile), [instruction reference](https://docs.docker.com/reference/dockerfile/)                                                                 |
| Build context             | `.dockerignore` allows required inputs and excludes local `.env`, Git history, mutable data and host build output from the build context.                                                                                                          | [.dockerignore](../../../.dockerignore)                                                                                                                                   |
| Docker CLI                | `docker build` creates an image; `docker run` starts a container; `docker ps` lists running containers; `docker logs` reads output; `docker stop` stops a container.                                                                               | [Dockerfile](../../../Dockerfile), [README](../../../README.md#docker-compose)                                                                                            |
| Ports and Compose         | `127.0.0.1:${PORT:-8080}:8080` maps the localhost port (default `8080`) to container port `8080`. [Compose](https://docs.docker.com/compose/) manages services, networks and volumes; this project defines one API service and its storage volume. | [compose.yaml](../../../compose.yaml)                                                                                                                                     |

After starting Docker and preparing `.env` as described in the README, run `docker compose up --build --wait` from the backend root (PowerShell 7+ and Bash).
